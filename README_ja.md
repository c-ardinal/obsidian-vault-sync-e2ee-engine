# Vault Syncer E2EE Engine

[ [🇺🇸 English](README.md) | [🇯🇵 日本語](README_ja.md) ]

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

[Vault Syncer](https://github.com/c-ardinal/obsidian-vault-syncer) 専用の外部E2EEエンジンです。  
Vault Syncer がアップロードする Vault 内ファイルの内容を端末上で暗号化し、ダウンロード時にローカル上で復号します。  
クラウド側でファイル内容を参照する手段はありません。ただし、ファイル名・フォルダ名・サイズ・更新日時は暗号化**対象外**です（[保護範囲](#-保護範囲) を参照）。

---

## ✨ 機能

- **AES-256-GCM 暗号化**:
    - 業界標準の認証付き暗号化で全 Vault ファイルを保護
- **パスワードによるマスターキー保護**:
    - ファイルは乱数生成の256ビットマスターキーで暗号化します。マスターキーは PBKDF2-HMAC-SHA512（210,000 回、ランダムソルト）でパスワードから導出した鍵で保護します
- **ファイル単位のランダム IV**:
    - 暗号化処理単位で一意の初期化ベクトルを使用し、暗号文のパターン分析を防止
- **パスワード強度チェッカー**:
    - 新規パスワードの強度を表示（内蔵の簡易判定）。新規パスワードには12文字以上、かつ強度「弱」以外の判定が必要です
- **自動ロック解除**:
    - 初期状態は無効です。有効化時はパスワード由来の値を Obsidian の SecretStorage に保存するため、端末へのアクセス権限を持つ人物は Vault を復号可能です
- **透過的な統合**:
    - Vault Syncer のスマート同期（3-way マージ、競合検出、履歴表示）が暗号化データでもシームレスに動作
- **ワンクリック移行**:
    - セットアップウィザードが既存 Vault データの暗号化と整合性検証を自動処理

## ⌨️ 設定画面とコマンド

E2EE Engine のインストール後、Vault Syncer の **設定 → アドオン** に **セキュリティ (E2EE)** ページが表示されます（Vault Syncer 0.19 以降）。暗号化ステータスと、現在の状態で実行可能な操作（暗号化の開始、ロック解除、パスワード変更、リカバリーコード、復元）のみを表示し、起動時の自動ロック解除も設定可能です。

同一の操作は Obsidian のコマンドパレットでも実行可能です（コマンドIDは従来と同一のため、既存のホットキーもそのまま使用可能）:

| コマンド                                | 説明                                         |
| --------------------------------------- | -------------------------------------------- |
| E2EE: Vaultの暗号化を開始する           | 非暗号化 Vault で E2EE を初期化              |
| E2EE: Vaultのロックを解除する           | ロック中の Vault をパスワードで解除          |
| E2EE: 暗号化パスワードを変更する        | マスターキーを新パスワードで再ラッピング     |
| E2EE: リカバリーコードを表示する        | リカバリーコードと鍵フィンガープリントを表示 |
| E2EE: リカバリーコードでVaultを復元する | リカバリーコードで Vault アクセスを復元      |

## 🚀 インストール

注意: E2EEは一度有効化すると無効化できません。E2EEを使用せずに本プラグインの使用を継続したい際は、 [#復旧手順](#️復旧手順) を実行してください。

### Vault Syncerの設定画面から導入（推奨・スマートフォン対応）

1. Vault Syncerの設定画面「アドオン」の **アドオンを導入...** をタップ（またはコマンドパレットから `Vault Syncer: アドオン導入画面を表示` を実行）
2. **ダウンロードページへ移動** をタップし、最新リリースの `vault-syncer-e2ee-engine.zip` をダウンロード
    - zipにはエンジンと[追加利用条件](TERMS_ja.md)が同梱されています。最新以外のバージョンは、Vault Syncerが拒否するため使用不可能です。
3. **ファイルを選択** でダウンロードしたzipを選択。Vault Syncerが検証し、追加利用条件を表示します
4. 追加利用条件を確認して同意し、**導入する** をタップ。再起動不要で有効化されます
5. Vault Syncerの設定画面 **アドオン → セキュリティ (E2EE)** の「暗号化の開始」で **開始** をタップ（またはコマンドパレットから `E2EE: Vaultの暗号化を開始する` を実行）し、セットアップウィザードを完了してください

他デバイスで暗号化済みのVaultでは、起動時に導入ダイアログを自動表示し、導入後は直接パスワード入力に移行します。

### 手動コピーで導入（上級者向け）

1. [リリースページ](https://github.com/c-ardinal/obsidian-vault-syncer-e2ee-engine/releases) から最新バージョンの `e2ee-engine.js` をダウンロード
2. Vault Syncer のプラグインディレクトリに配置:
    ```
    <Your Vault>/.obsidian/plugins/cardinal-vault-syncer/e2ee-engine.js
    ```
3. Obsidian を再起動し、Vault Syncerの設定画面 **アドオン → セキュリティ (E2EE)**（またはコマンドパレット）から暗号化を開始

手動で導入した際も、[追加利用条件](TERMS_ja.md)に同意したものとみなされます。

### ソースからビルド

1. 依存関係をインストール:

    ```bash
    npm install
    ```

2. エンジンをビルド:

    ```bash
    npm run build
    ```

3. `dist/e2ee-engine.js` をプラグインディレクトリにコピー:
    ```
    <Your Vault>/.obsidian/plugins/cardinal-vault-syncer/e2ee-engine.js
    ```

`npm run build` は `dist/vault-syncer-e2ee-engine.zip`（Vault Syncerがインポートするアドオンパッケージ: マニフェスト `addon.json`・エンジン・利用条件）も出力し、Vault Syncerが固定している各ファイルのSHA-256ハッシュを表示します。エンジン・バージョン・`TERMS` ファイルのいずれかを変更した際は、新規ハッシュを反映したVault Syncerのリリースが必要です。

## 🔒 セキュリティアーキテクチャ

### Vault Lock

`vault-lock.vault` ファイルは暗号化された Vault と一緒に保存され、以下の情報を格納します:

- パスワード由来の鍵で暗号化したマスターキー
- PBKDF2 のソルト

ファイル全体も同一の鍵導出から得た別の鍵で暗号化済みのため、パスワード無しでは内容を判別できません。

このファイルは Vault のロック解除に必要です。データの復号には、このファイルとパスワードの両方が必須です。  
このファイルはローカルには保管されず、クラウドストレージ上の以下の場所に格納されます。

```
  <Your Vault>/.obsidian/plugins/cardinal-vault-syncer/data/remote/vault-lock.vault
```

（プラグインID変更前に設定済みの Vault では、`cardinal-vault-sync/` および `obsidian-vault-sync/` 配下にも同一ファイルを保持します。）

### 🛡 保護範囲

- **暗号化対象**: 同期対象の全ファイルの内容、および Vault Syncer のインデックス（ファイル一覧とハッシュ値）。
- **暗号化対象外**: ファイル名・フォルダ名・パス、ファイルサイズ（概算値）、更新日時、ファイル数、変更の発生時刻。ファイル名に秘密情報を記載しないでください。
- **改ざん検知**: 暗号化された内容の改変は検知します。大容量ファイルでは、チャンクの順序入替・欠落・他ファイルからの移植も検知します。それ以外のファイルでは、クラウドストレージへの書込権限を持つ人物が、2ファイル間の暗号文の交換や旧バージョンへの差戻しを実行した際、検知できません。
- **パスワード変更でマスターキーは変更されません。** 旧パスワードと旧 `vault-lock.vault`（Google Drive ではバージョン履歴に約30日間残存）の両方を所持する人物、またはリカバリーコードの所持者は、引き続き復号可能です。リカバリーコードはマスターキーそのものであり、有効期限はありません。流出の疑いがある際は [復旧手順](#復旧手順) で Vault を再作成し、新規のマスターキーへ移行してください。
- **脆弱なパスワード**: `vault-lock.vault` の所持者は、オフラインでパスワードの総当たり試行が可能です。PBKDF2 で試行速度は低下しますが、短文や頻出語のパスワードは短時間で突破されます。十分な長さのパスフレーズを使用してください。

## 🔧 技術仕様

| 項目         | 値                                                          |
| ------------ | ----------------------------------------------------------- |
| フォーマット | CommonJS (CJS)                                              |
| 暗号化方式   | AES-256-GCM（Web Crypto API）                               |
| マスターキー | 乱数生成の AES-256 鍵（AES-GCM で鍵ラップ）                 |
| 鍵導出       | PBKDF2-HMAC-SHA512、210,000 回、16 バイトのランダムソルト   |
| IV サイズ    | 12 バイト（操作単位でランダム生成）                         |
| 大容量ファイル | チャンク形式（VSC3）: 各チャンクをファイルと位置に結合     |
| ローダー     | Vault Syncer が SHA-256 照合後、モジュールとしてロード |

## ⚠️ 重要な注意事項

- **パスワードを厳重に管理してください**:
    - パスワードとリカバリーコードの両方を紛失した際は、暗号化されたデータの復号は不可能です。「リカバリーコードを表示する」コマンドでバックアップ用リカバリーコードをエクスポートし、安全な場所に保管してください。
    - 開発者であっても復元は不可能です。
- **vault-lock.vault をバックアップしてください**:
    - クラウドストレージにのみ存在します。このファイルは復号に不可欠です。紛失するとデータの復元は不可能です。
    - 開発者であっても復元は不可能です。
- **マルチデバイス**:
    - Vault を共有する全デバイスで同一のパスワードを使用する必要があります。特定のデバイスで E2EE を有効化すると、他デバイスでは次回同期時にパスワード入力を要求します。

## ❗️トラブルシューティング

### パスワード/リカバリーコード/vault-lock.vaultの紛失時

クラウドストレージ上のデータは**如何なる手段でも復号できません**。そのため、同期や履歴参照などの機能も利用不可能です。  
E2EEを使用せずに本プラグインの使用を継続したい際は、 [#復旧手順](#️復旧手順) を実行してください。

### E2EEの無効化

一度有効化したE2EEの無効化は不可能です。  
E2EEを使用せずに本プラグインの使用を継続したい際は、 [#復旧手順](#️復旧手順) を実行してください。

### 復旧手順

注意: 以下の手順を実行すると、プラグインの設定やファイルの変更履歴など、**Vault Syncerプラグイン関連の全データが消失します**。

1. Obsidian外の操作:ブラウザやクラウドストレージのアプリから、クラウドストレージ上のVaultフォルダ(デフォルト設定では、ObsidianVaultSync配下)を削除する。
2. Obsidianの設定 > コミュニティプラグイン > インストールされたプラグイン からVault Syncerをアンインストールする。
3. Obsidianを再起動する
4. Obsidianを起動し、設定 > コミュニティプラグイン > 閲覧 からVault Syncerを再インストールする。
5. Vault Syncerの設定からログインし、Vaultをクラウドストレージへアップロードする。
